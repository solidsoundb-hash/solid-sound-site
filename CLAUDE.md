# Solid Sound (solid-sound.net) — правила для Claude Code

Задание: `docs/TZ-claude-code-speed.md`. Прочитай его целиком перед работой.

- Над сайтом работают два Claude (A — облако, B — компьютер владельца). Перед любой работой: `git pull --rebase`, прочитай `docs/SYNC.md` (правила, «Сообщения», «Сделано») и свежие строки `docs/owner-preferences.md` — указания владельца, данные одному Claude, действуют для обоих (правило 8 в SYNC.md; владелец, 15.11.2026).

- С владельцем (Grenor) говори по-русски, коротко. Тексты для клиентов пиши по-английски.
- ВСЁ, что видит владелец, — только по-русски: ответы, короткие пояснения по ходу работы («что делаю сейчас»), подписи к командам. Ни одной фразы по-английски (владелец, 17.11.2026: «Пиши на русском, добавь в инструкцию сейчас же»).
- Сайт должен быть очень быстрым: минимум кода, никаких `setInterval` для слежки за DOM. Вместо них — `MutationObserver` + `requestAnimationFrame`. Скрипты подключай с `defer` и только на нужных страницах.
- Слабые телефоны (владелец, 20.11.2026, Samsung A31: «реально тормозит, а на айфоне норм»): каждую правку проверяй и на слабом Android (A31, ~412×780), не только на iPhone/ПК. Для слабых устройств есть облегчённый режим `html.ss-lite` (`modules/adaptive.php`: телефон с ≤4 ГБ, низкий FPS, экономия трафика, медленная сеть) — тяжёлые эффекты (размытие, большие тени, анимации, предзагрузка) там выключай.
- СКРИНЫ ДО И ПОСЛЕ — ВСЕГДА, для всех Claude и всех разделов сайта (владелец, 20.11.2026: «всегда скринить до и после правок перед тем как что-то делать и после того как что-то выкладывать и говорить что это готово»): перед правкой — снимок того, что есть сейчас (робот `home-look` / `photo` / `creator-audit`, ПК 1280–1366 + телефон 412×780 и 412×700); после выкладки — такие же снимки, сам их смотришь и сравниваешь. «Готово» владельцу — только после того, как посмотрел снимки «после» и всё ровно; в ответе — что было и что стало.
- Телефоны — всё компактно (владелец, 20.11.2026): шапка и заголовки поуже, крупные кнопки чуть меньше, большие отступы чуть меньше; главный блок (слайдер) должен целиком влезать в экран над нижней панелью; свайп — лёгкий (дуга пальцем тоже считается).
- Работай быстро, но проверяй себя:
  - Lighthouse до и после;
  - скриншоты на 390 px и 1280 px;
  - чек-лист функций из ТЗ.

  Сдавай только работающее.
- Без «ок» владельца: ничего не меняй на живом сайте, ничего не плати (цену называй заранее), ничего не публикуй.
- Сначала бэкап, потом staging, потом прод.
- Дизайн и функции сохраняй 1-в-1.

## Как устроено (ноябрь 2026)
- `plugin/solid-sound-custom/` — плагин на сайте. `includes/custom.php` — замороженный оригинал (`?ss_v2=0`), `src/` — рабочие исходники, `build/` — собранная версия (`node tools/build.mjs`), её видят по `?ss_v2=1` или всем при `SS_BUILD_DEFAULT=true`.
- Выкладка: правка `.github/deploy.txt` → GitHub Action `deploy.yml` (бэкап с сервера, заливка по FTP, проверка, автооткат). Забрать файлы с сервера: правка `.github/ftp-pull.txt` → `live/`.
- `tools/compare.js` — скриншоты старой и новой версии и разница в пикселях.
