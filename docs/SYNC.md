Над сайтом работают два Claude Code одновременно:

- **B — компьютер владельца** (Claude Code CLI).

Напрямую друг другу писать они не могут, поэтому договариваются **через этот файл в GitHub**.

## Правила (обязательно для обоих)

1. **Перед любой работой**: `git pull --rebase`, прочитать раздел «Сейчас в работе» и «Сообщения».
2. **Занять участок**: дописать свою строку в «Сейчас в работе» (кто, что, какие файлы/папки, время UTC),
   сразу `git commit -m "sync: A берёт …"` и `git push`. Только после этого начинать правки.
3. **Чужой участок не трогать.** Если без него никак — написать в «Сообщения» и ждать ответа
   (или спросить владельца). Строке старше 3 часов без новых коммитов можно не верить — но написать об этом.
4. **Выкладка (`.github/deploy.txt`)**: перед добавлением строки — `git pull --rebase`, номер = последний + 1.
   Если `push` отклонён — снова `pull --rebase`, перенумеровать, пушить. **Ждать предыдущую НЕ нужно** (с 15.11.2026):
   устаревшие выкладки отменяются сами — в очереди GitHub оставляет только последнюю, а запуск, у которого на main
   уже есть более новая строка, ничего не заливает (шаг «Skip if a newer deploy is already queued» в deploy.yml).
   Идущая заливка не прерывается (иначе сайт останется наполовину залитым). Строку добавлять, когда изменения уже запушены.
5. **Собранные файлы (`plugin/solid-sound-custom/build/`)**: после `pull` всегда заново `node tools/build.mjs`
   перед коммитом — иначе можно затереть чужую сборку старой.
6. **Закончил** — убрать свою строку из «Сейчас в работе», коротко записать итог в «Сделано» и запушить.
7. Владелец говорит с обоими. Если он дал разные указания — не спорить, написать в «Сообщения» и спросить его.
8. **Одно действие владельца — для обоих (правило владельца 15.11.2026).** Владелец может сказать что-то любому из нас;
   второй должен подхватить это автоматически, без повторного объяснения:
   - каждое новое указание, правило или решение владельца записывать СРАЗУ: правило/предпочтение → `docs/owner-preferences.md`
     (дата + слова владельца), задача → «Задачи от владельца», сделанное → «Сделано», вопрос/договорённость для второго → «Сообщения»;
   - любые общие механизмы (выкладка, роботы, проверки, тестовые учётки, секреты по именам) делать так, чтобы ими пользовались оба
     (общие файлы в репозитории, а не у себя в сессии), и записывать в SYNC.md, как ими пользоваться;
   - в начале каждой сессии/задачи: `git pull --rebase`, прочитать «Сообщения», «Сделано» (сверху) и свежие строки `owner-preferences.md`
     и применять их так же, как если бы владелец сказал это тебе;
   - если указание противоречит тому, что делает второй, — не переделывать молча, написать в «Сообщения» и спросить владельца.
