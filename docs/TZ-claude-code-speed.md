# ТЗ для Claude Code: скорость и бэкенд solid-sound.net

Владелец: Grenor (Sølid Søund Studio). Отчёты — по-русски, коротко. Тексты для клиентов — по-английски.
Сайт: https://solid-sound.net — WordPress + WooCommerce + тема Impreza (WPBakery) + Polylang + WCFM + Tidio + AI Engine.

## Главная цель
Сделать сайт максимально быстрым и при этом сохранить весь текущий вид и функции 1-в-1.

Целевые метрики (PageSpeed, мобильная версия, на страницах `/en/`, `/en/all-products/`, на любой карточке товара и на `/Services-Calculator/`):
- LCP < 2.5 s;
- INP < 200 ms;
- CLS < 0.1;
- TTFB < 600 ms;
- Performance ≥ 90.

## Правила работы
1. **Первым делом сделай полный бэкап** (файлы + база) и проверь, что он восстанавливается. Если хостинг позволяет — работай на staging.
2. **Ничего не плати и не подключай платное** без «ок» владельца. Заранее назови цену. Пример: WP Rocket стоит примерно от $59 в год — уточни на сайте.
3. **Не меняй рабочий сайт без «ок»** владельца. Порядок такой: staging → проверка → короткий отчёт → «ок» → прод.
4. **После каждого шага проверяй сам:**
   - Lighthouse до и после, на мобильном и десктопе;
   - скриншоты на ширине 390 px и 1280 px;
   - чек-лист функций ниже.

   Сдавай только работающее.
5. **Работай быстро и чисто.** Минимум кода, никаких таймеров `setInterval` для «досмотра» DOM. Вместо них — `MutationObserver` + `requestAnimationFrame`, только по событиям.
6. **Весь свой код держи в git**, в одном плагине — см. ниже. Каждое изменение — отдельный коммит с понятным описанием.

## Задачи

### 1. Один плагин вместо вставок
- Создай mu-plugin или плагин `solid-sound-core` (git).
- Вынеси весь CSS/JS из страниц 2433, 2, 52 и 2561 в статические минифицированные файлы с версией в имени.
- Подключай их через `wp_enqueue_*` — `defer`, и только на тех страницах, где они нужны.
- Длинный кэш для статики: `Cache-Control: max-age=31536000, immutable`.
- Общее меню отдавай обычным статическим `.js` (кэш браузера и CDN) — без gzip-в-base64, без `localStorage` и без `new Function`.
- Патчи главной примени к исходнику один раз и собери итоговый файл. Никаких правок текста на лету.
- Из контента страниц убери вставки — после переноса и проверки, что всё работает так же.

### 2. Главная: быстрый первый экран
- Первый экран (шапка + hero) должен отдаваться готовым HTML с сервера, без ожидания React. React и остальное приложение — потом.
- React захости у себя или замени на заранее собранный бандл. Без лишних запросов к CDN.
- Шрифт Exo 2: захости у себя, только нужные начертания и латиница, `preload` + `font-display: swap`.

### 3. Сервер и кэш
- Страничный кэш. Если хостинг на LiteSpeed — бесплатный LiteSpeed Cache; иначе предложи варианты с ценой.
- Brotli/gzip, HTTP/2 или 3.
- Предложи Cloudflare (бесплатный тариф).
- Если хостинг поддерживает — Redis object cache.
- WooCommerce: отключи cart fragments там, где нет корзины; убери ассеты WooCommerce, WCFM и Polylang со страниц, где они не нужны.
- База: почисти autoload-опции, просроченные transients, ревизии.

### 4. Картинки и аудио
- Обложки → WebP/AVIF, `srcset`, явные `width`/`height`. Картинки ниже первого экрана — `loading="lazy"`.
- Демо MP3:
  - `preload="none"`, поддержка Range-запросов, длинный кэш, правильный Content-Type;
  - preconnect/preload только для первого трека;
  - превью должны стартовать мгновенно и без заиканий.

### 5. Третьи скрипты
- Tidio, Meta Pixel, GA4, WCFM — грузить после первого взаимодействия или по `requestIdleCallback`.
- Аналитика при этом должна продолжать считать: `page_view`, `play_demo`, `generate_lead`, `search`, `add_to_cart`, `purchase`.
