# Роль: Копирайтер (тексты и переводы)

Сначала — `docs/team/README.md`. Здесь — только своё.

## Миссия
Посетитель на своём языке за 5 секунд понимает: что это, почему стоит купить, как купить. Тексты продают, а не украшают.

## Языки по важности (22.11.2026)
DE → FR → ES → UA → IT → PT. Английский — основной, все новые тексты сначала на нём.

## Порядок работы над переводами
1. Путь к покупке: ссылки шапки и кнопки главной на свой язык → товар/каталог → корзина/оформление → Services & Prices и
   калькулятор → Free / Sell → FAQ → юридические → статьи.
2. Окно входа/регистрации.
3. Остальное.

## Правила текста
- Пишем для музыкальных продюсеров и DJ: просто, конкретно, выгода в первой фразе. Без канцелярита и «воды».
- Перевод — как у носителя, не дословный. Термины продюсеров (stems, mixdown, preset, template) оставлять, как говорят в
  этой стране.
- Не переводить: названия товаров, бренды, цены, BPM/Key. Цены — не писать вручную со знаком валюты (у посетителя может
  быть другая валюта: `window.ssMoney`).
- Юридические формулировки (лицензия, возврат) — только из FAQ/License, ничего не выдумывать.
- Длина: на телефоне A31 текст кнопки — в одну строку; заголовок — до 2 строк.

## Как устроены переводы (проверить и дополнить)
- Главная: `src/home/i18n/<язык>.json` — ключ = точный английский текст строки в шаблоне; подставляется при сборке.
- Общая шапка: `src/ss-global.js`. Формы: `modules/i18n-forms.php`. Остальные страницы: `modules/translate.php` (разобраться).

## Проверка
- Снимки до/после на ПК и A31 для каждого языка, который трогал; кликнуть ссылки шапки — ведут на свой язык.
- Ничего не вылезает за кнопки/карточки на 412 px.

## Приёмы
- **Как устроено на самом деле (22.11, разобрано):**
  - Polylang-копии есть только у главной, Templates/Presets/Music/Contacts и вики (у каждого языка своя страница). Товары, каталог,
    корзина, оформление, кабинет — НЕ копии: `custom.php` (блок `ss_lang_url`) отрезает `/de/` от адреса и включает язык
    (`$GLOBALS['ss_forced_lang']`), страница та же английская.
  - Подписи магазина (кнопки, корзина, фильтры) переводят старые словари в `custom.php`: `ss_ui_dict()` (ua/de/fr/pt),
    `ss_ui_dict2()`; описания нескольких товаров — `ss_prod_dict()`. Для es/it их почти нет.
  - `modules/translate.php` — это НЕ перевод сайта, а переводчик описаний для авторов (Add Product → английский).
  - **Новый способ (Копирайтер, 22.11): `modules/i18n-pages.php`.** Страницы из `ss_vp_slugs()` (all-products, services-prices,
    studio-calculator, free, sell, faq, юридические…) открываются по `/de/<страница>/` — это английская страница, а сервер меняет
    видимый текст по словарю `modules/i18n-dict-<язык>.php` (ключ = точный английский текст, как в браузере, пробелы схлопнуты).
    Тексты, которые печатают скрипты (шапка, калькулятор), меняет маленький «обходчик» с тем же словарём. Включён язык —
    только если он в `ss_vp_langs()`. Ссылки шапки на эти страницы — `tr()` в `ss-global.js` (смотрит `window.ssVPL`).
  - Чтобы собрать английские тексты страницы: робот `tools/probe/texts.js` (строка «texts» в `.github/probe.txt`) →
    ветка `shots-ab`, `probe-texts/texts.json` (srv:1 — текст есть в HTML сервера, srv:0 — его печатает скрипт).
  - Текст, разорванный тегами (`Pay <b>50%</b> now`), — это 3 отдельных ключа: «Pay», «50%», «now». Переводить кусками.
