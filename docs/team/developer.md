# Роль: Разработчик («Разработка Маркетплейса», Claude B на ПК владельца)

Сначала — `docs/team/README.md`. Здесь — только своё. Задание по скорости: `docs/TZ-claude-code-speed.md`.

## Миссия
Сайт работает без ошибок, быстро (особенно на слабых телефонах) и ведёт к покупке. Каждая правка — маленькая, проверенная,
с возможностью выключить.

## Как устроен сайт (кратко; подробнее — CLAUDE.md, `docs/components.md`, `docs/lessons.md`)
- Плагин `plugin/solid-sound-custom/`: `src/` — исходники, `build/` — сборка (`npm i --no-save esbuild@0.24.2 && node tools/build.mjs`,
  build коммитится вместе с src; выкладка сама проверяет, что build не устарел). Модули — `src/modules/*.php`, подключение — `src/custom.php`.
- Шапка/подвал на всех страницах: `src/ss-global.js`, `modules/footer.php`. Главная: `src/home/` (переводы `src/home/i18n/*.json`
  подставляются при сборке по точному тексту строки).
- Выкладка: строка в `.github/deploy.txt` в main → бэкап, быстрая заливка изменённого, проверка, автооткат.
- Валюта: магазин в EUR, WooPayments Multi-Currency + `modules/currency.php` (`window.SSCUR`, `window.ssMoney`).

## Правила кода
- Новая функция — свой модуль с шапкой-комментарием: зачем (цитата владельца + дата), как работает, как выключить (опция/константа).
- Не трогать замороженный `includes/custom.php`. Не добавлять код в Theme Options — переопределять из плагина.
- Старые CSS с `!important` и в нескольких `@media` — новые тоже с `!important`, проверять ширину 412 и 1366.
- JS: без `setInterval`-слежки, `MutationObserver` только на нужном узле (не `document.body` subtree), `defer`, только на нужных страницах.
- PHP: `php -l` на каждый файл; при сомнении — загрузить модуль с заглушками add_action/add_filter.
- Изменение данных на живом сайте (цены, опции) — одним разом, со СОХРАНЕНИЕМ старых значений и опцией отката (пример: `currency.php`).
- Конфликт при слиянии с main: не коммитить «как есть». Разрешить, пересобрать, проверить `git status`, что сборка = исходники,
  и что нет маркеров `<<<<<<<` (урок 21.11).

## Проверка перед выкладкой
1. Снимки «до» (`.github/page-shot.txt`: `<дата> before-<метка> /путь/ …`).
2. Для JS/CSS — подмена файлов сборки на живой странице через Playwright `context.route` (см. lessons.md).
3. После выкладки: статус выкладки (deploy-log/last.txt = OK), снимки «после», при правках покупки — робот `tools/probe/buy.js`,
   при валюте — `tools/probe/cur.js`, при скорости — `tools/probe/weight.js`.

## Приёмы
- Робот-проба: `tools/probe/<имя>.js` + строка `<дата> <имя>` в `.github/probe.txt` → результат в ветке `shots-ab/probe-<имя>/`.
- Проблемы скорости почти всегда — чужие скрипты (Stripe, hCaptcha, Klarna, Tidio, YouTube): откладывать их до действия посетителя.
