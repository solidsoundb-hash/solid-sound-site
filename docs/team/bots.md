# Рой роботов у каждого сотрудника (владелец, 25.11.2026)

Владелец: «под каждого сотрудника нужен рой своих ботов, который расширит их лимиты, возможности и придаст скорость и автономность». «Мы строим огромную цифровую империю».

## Как устроено
- Робот = GitHub Action (`.github/workflows/*.yml`) + скрипт в `tools/`. Репозиторий публичный → роботы бесплатны, работают 24/7 и не тратят лимиты чатов.
- Робот делает рутину (собрать, проверить, сравнить, снять снимки) и кладёт отчёт в `reports/<роль>/` или на ветку снимков. Сотрудник утром читает отчёты и решает, что делать (думает и решает человек-роль, рутину делают роботы).
- Внутри чата — подагенты (Agent) для параллельной работы, но они тратят лимит: использовать для больших разовых задач, не для рутины.
- Каждый робот учится: хранит память в `reports/<роль>/memory.json` (что было полезно / шум) и раз в неделю роль улучшает его по этой памяти.
- Правила: без секретов в коде (только GitHub Secrets по имени), без платных API без цены и «ок» владельца, расписание — вне 06–09 Pacific, минута не :00.

## Обучение и тренировки (владелец, 25.11: «роботы должны обучаться и становиться лучше… тренировки на мелких задачах перед тем как давать большие… Время — самый ценный ресурс после денег»)
**Лестница тренировок — каждый робот проходит её по ступеням, на следующую только после зачёта:**
1. **Ступень 1 — одна мелочь.** Одна страница / один конкурент / один запрос. Запуск вручную (`workflow_dispatch`), прогон ≤ 5 мин. Роль сверяет результат глазами с правдой («эталон» — что сама нашла вручную).
2. **Ступень 2 — маленький набор.** 5–10 страниц/объектов, 2 прогона подряд. Зачёт: ≥ 90 % верных находок, ≤ 1 ложной тревоги, ни одной пропущенной важной.
3. **Ступень 3 — полный объём по расписанию.** Только после зачёта 2. Первую неделю роль читает каждый отчёт.
Провал ступени → чинить на ТОЙ ЖЕ ступени, не идти дальше. Не запускать большой прогон «на авось» — это трата времени.

**Как робот учится (обязательно у каждого):**
- Экзамен: `tools/bots/<робот>/exam.json` — 5–20 примеров с правильным ответом. Перед каждым изменением робота — прогон экзамена; хуже прежнего — изменение не принимается.
- Память: `reports/<роль>/memory.json` — что было полезно (роль отметила «пригодилось»), что шум. Робот читает память и сам отсеивает повторяющийся шум.
- Раз в неделю роль: смотрит память, добавляет новые примеры в экзамен (особенно ошибки робота), улучшает робота, записывает оценку в таблицу ниже (точность, ложные тревоги, минут на прогон, польза для продаж).
- Робот, который 2 недели не дал пользы, — выключить.
