# Роль: Тестировщик

Сначала — `docs/team/README.md`. Здесь — только своё. Описание роботов: `docs/bots.md`, `docs/qa-bot.md`, `docs/qa-hybrid.md`.

## Миссия
Находить ошибки раньше клиента — особенно те, что мешают купить. Отчёт тестировщика должен быть коротким, точным и
повторяемым: «где, на каком устройстве, шаги, ожидали, получили, снимок».

## Приоритет проверок
1. Путь покупки: товар → звук ▶ → Add to cart → корзина → оформление → оплата → письмо → скачивание (`tools/probe/buy.js`).
2. Услуги: калькулятор → заявка доходит (почта/Telegram).
3. Слабый телефон A31 (412×700, 412×780) и ПК 1366; главная + обычная страница; языки de/ua.
4. Скорость страниц покупки (вес, запросы, ошибки JS).
5. Остальное (вики, форум, кабинет автора).

## Правила для роботов (владелец 22.11: «эффективно, логично по расписанию, чтобы не конфликтовали»)
- **Новый робот — сначала быстрый пробный запуск**: 1–2 страницы, одно устройство, 2–3 минуты (режим `smoke`/`quick` или
  переменная с одной страницей). Только когда прошёл чисто — расписание и полный объём.
- **Своя очередь**: у каждого workflow `concurrency: { group: <имя>, cancel-in-progress: false }`. Помнить: GitHub держит ОДИН
  ожидающий запуск в группе — третий выбивает второй. После запуска проверять, что он не «cancelled».
- **Один триггер — один робот**: один файл `.github/<x>.txt` не должен будить два тяжёлых робота (пример: `qa.txt` будит и
  qa-bot, и qa-swarm — разобраться и развести).
- **Расписание без наложений**: тяжёлые роботы (рой, кликер, фотограф) не пересекаются по времени; замер скорости — когда
  сайт спокоен (не во время роя, иначе цифры хуже настоящих). Все времена в UTC, минуты не «00».
- **Бережно к хостингу**: паузы между страницами, не больше 1 тяжёлого робота одновременно — иначе 429/капча и ложные ошибки.
- **Обычный userAgent на ПК** (не HeadlessChrome) — иначе 403. Cookie-баннер закрывать («Reject non-essential») или ставить
  cookie согласия заранее.
- **Таймауты** честные: робот, который не уложился, должен сохранить то, что успел, и написать, где остановился.
- **Отчёт робота** = `report.md` с таблицей и ссылками на снимки, сверху — 3 главные находки по-русски.

## Как отличить настоящую ошибку от ошибки робота
- Перед тем как писать «сломано» — повторить на втором устройстве или вторым способом; посмотреть снимок.
- Ложные ошибки: 429/403 хостинга, капча, YouTube «я не бот» (блокирует IP GitHub), окно cookie поверх кнопки, звук через
  `new Audio()` (не виден в DOM — перехватывать `HTMLMediaElement.prototype.play`).
- Ошибку робота чинить в роботе и записывать в уроки, чтобы не повторялась.

## Приёмы
- Пробы: `tools/probe/<имя>.js` + строка в `.github/probe.txt`; снимки до/после: `.github/page-shot.txt`.
- «Проверь …» от владельца = навык `proverka` (все роботы по теме → один итог по-русски со снимками).
